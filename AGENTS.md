# AGENTS.md

## Project Overview
qualified-opinion/tonnage is a private, offline-only strength training logger for Android (a Hevy replacement without social features), built with Kotlin, Jetpack Compose, Material 3 and Room. It follows the same setup as Piso.

- **Package Name / Application ID**: `com.janreins.tonnage`
- **Database**: On-device SQLite via Room (`tonnage_database`), schemas exported to `app/schemas`.
- **Network**: None. No remote API calls, analytics or cloud sync.
- **Exercise library**: `app/src/main/assets/exercises.json`, a trimmed copy of free-exercise-db (public domain), seeded into Room by `ExerciseRepository.seedLibrary`, which adds missing built-ins once per app version and never touches existing rows. An empty library is always seeded. The successful version code is stored in SettingsStore for the supplied context only after seeding; the cheap tracking-type repair still runs every launch.

## Key Build & Test Commands
- **Run Unit Tests**: `./gradlew test`
- **Lint**: `./gradlew lintDebug`
- **Build Debug APK**: `./gradlew assembleDebug`
- **Build Release APK**: `./gradlew assembleRelease`

## Codebase Conventions & Constraints
- **Offline Integrity**: Do not add network calls, remote API integrations, or cloud sync services.
- **Units**: Store weights in kg; converting to lb is display-only.
- **Schema changes**: Any Room entity change needs a version bump and a migration with a test. Never use destructive migration; users' workout history must survive updates.
- **Active workout**: a `workouts` row with `endedAt = null`. Every edit goes straight to Room (`WorkoutRepository`), so nothing lives only in memory. `WorkoutSession.confirmedInThisProcess` decides whether to show the resume/discard prompt after process death.
- **Rest timer**: `timer/RestTimer` holds the countdown (elapsed-realtime clock); `service/WorkoutService` is a `specialUse` foreground service that waits it out under a partial wake lock and vibrates/notifies when it ends. Keep the wake lock bounded by the rest length. The rest is synchronously checkpointed in separate `rest_timer` preferences on start/adjust and cleared on finish/skip/discard. Recovery checks elapsed remaining against the total, rejects elapsed time before the checkpoint (reboot), and requires wall-clock remaining within 3 seconds. Expired or mismatched rests are cleared. Confirmed workouts retry a missing service on activity resume; the service and visible fallback claim timer completion atomically before the same alarm-usage vibration. Check both app notifications and the rest-done channel; permission is requested once per workout when starting or accepting resume.
- **Routines**: `routines` → `routine_exercises` → `routine_sets`. The editor keeps `RoutineDraft` (`ui/routines`) plus its original in `SavedStateHandle` as bounded JSON (32,000 UTF-16 characters, about 64 KiB). Oversized drafts remain editable with a Save-before-leaving notice, and their checkpoint is removed; shrinking restores recovery. Save and Cancel clear the checkpoint. It saves the routine in one transaction (`RoutineDao.save`); it reuses the workout screen's `ExerciseCard` by mapping the draft to `ExerciseBlock`s. `workouts.routineId` records the routine a workout was started from; it is deliberately not a foreign key so deleting a routine keeps history.
- **Previous values**: `WorkoutRepository.previousSets` takes the completed sets from the latest finished workout of the same routine, falling back to the latest anywhere, and the card shows them by set index (no forced matching).
- **Personal records** are never stored: `WorkoutStats.recordsByWorkout` walks every completed working set in date order (`WorkoutDao.observeRecordSets`) and recomputes them, so editing or deleting old workouts stays correct. Each record kind needs an earlier value above zero for that kind; its first positive value establishes the baseline without a record. The finish screen's `detectRecords` uses the same rule and groups repeated exercise blocks before comparing. Record snapshots are deduplicated and calculated with `mapLatest` on `Dispatchers.Default`; only History/detail collect them, and editing pauses them until Done. With no subscribers, record work stops immediately.
- **Filled or blank sets** (batch 3): `SetInput.isFilled` decides per tracking type whether a set has anything logged. Ticking a blank set fills it from the previous set at the same index or is ignored; Finish offers to tick filled unticked sets and asks twice before discarding filled sets; `finishWorkout` also drops blank ticked sets. `SetInput.accept` is the one filter for every set cell (one decimal separator; caps 1000 kg, 1000 km, 999 reps, 99:59:59, which a stored value above them can still be shortened past).
- **Planned versus entered sets**: finish/remove checks compare unticked values with the routine target at the same set position, otherwise the preceding copied set. Matching values remain planned until ticked. This is a value comparison (no schema change), not a durable edit flag; identical retyping still needs a tick. Finish's secondary tick-and-save action only ticks entered sets. Blank ticked sets don't count in the preview, and finishing with no remaining exercises deletes the empty workout.
- **Editing a finished workout** writes straight to Room like logging; new sets are added already completed, and `tidyEdited` drops blank sets and empty exercises on Done and when opening a finished workout, recovering interrupted edits. Opening an active workout does not tidy it.
- **Hevy import** (`data/hevy`, `ImportRepository`): `HevyCsv` finds columns by header name (kg or lb, km or miles) and groups rows into workouts by title + start time. `ExerciseMatcher` tries a saved mapping, then an exact match on sorted name words, then `HevyAliases`, then a fuzzy word score; only LOW/NONE matches go to review. Every choice is saved in `hevy_mappings` (keyed by `ExerciseMatcher.normalizeName`), and workouts with `source = 'hevy'` and the same start time are skipped, so re-importing is safe. Add aliases only with ids that exist in `exercises.json` (`ExerciseMatcherTest` checks).
- **Backup** (`data/backup`): `BackupJson` writes `format` + `schemaVersion`. Bump `SCHEMA_VERSION` for any change a previous app version couldn't read, and keep `read` able to read every older version. Restore replaces workouts, routines, custom exercises and mappings in one transaction and is refused while a workout is in progress. Optional theme and Hevy import-zone settings stay in schema version 1: missing/unknown themes keep the phone's theme, the saved import zone is only filled if absent, and invalid zone ids are ignored.
- **Progress** (`domain/Progress.kt`, `domain/Milestones.kt`, `ui/progress`): everything is computed from `WorkoutDao.observeProgressSets` (completed working sets of finished workouts) and the finished workout list; nothing is stored, so no migration was needed. Weeks run Monday to Sunday in the phone's time zone. Progress uses an injectable clock/zone, refreshes at the next calendar midnight, and rereads time and zone on resume; use the same zone for weeks, muscles, streaks and milestones. Charts are drawn with Compose `Canvas` (`ui/components/Charts.kt`) rather than a chart library.
- **Body map** (`ui/components/BodyMap*.kt`): the anatomy art lives in `assets/body_map.txt`, generated by `tools/body-map/convert.py` from Ryan Graves' CC BY 4.0 SVGs; each muscle shape is tagged with a library muscle group and a part name. Keep the credit in `CREDITS.md` and in Settings (`BodyMapArt.CREDIT`), and keep every library muscle on the map (`BodyMapTest`).
- **Room migrations**: `MigrationTest` builds the previous schema by hand and opens it with the current app; add a case there for every new migration.
- **Room schemas** (batch 4): the generated JSON in `app/schemas` is committed, and CI fails when a build leaves `git status --porcelain app/schemas` non-empty (the log prints the file to commit). Commit the new JSON with every schema change.
- **Backup checks** (batch 4): routines and custom exercises keep their ids on restore, so `restore()` rejects repeated ids and a custom id equal to a built-in one, with a plain message, before deleting anything. `BackupJson.encode` refuses a file over `BACKUP_BYTE_LIMIT`, and `SettingsStore.lastBackupAt` is written only after the file is fully saved. Failed or cancelled exports try to delete the picker-created document; a provider refusing deletion must not mask the backup error.
- **Set cells**: Unicode decimal digits are normalized to ASCII before filtering. Colon times must parse, with minute/second parts at most 59; clearing remains allowed. Set inputs announce their row number, field and units; completion controls expose checkbox state, and set controls have at least 48 dp targets. Set rows are keyed by stored set id, and a completion pushes saved values through `CellFill` so focused cells update. Exercise-picker selection uses saveable state to survive recreation.
- **Workout clock**: only the top-bar subtitle reads the one-second clock. Set actions are remembered per ViewModel and read the latest workout through `rememberUpdatedState`.
- Navigation is a simple tab enum (`ui/state/MainTab`) plus screen state in `MainActivity`, as in Piso.
- Plan and acceptance notes for later phases live in the project files (`workout-app/plan.md`, `workout-app/implementation-notes.md`).
- How the app is built, the database, build and release: `HANDOVER.md` at the root.
- **Builders start with `docs/plan/BUILDER.md`.** The remaining work is GitHub issues #26 to #37, ordered in tracking issue #25: one PR per issue against `main`, `Closes #<n>`, PR template filled in. Reviews follow `docs/plan/REVIEW.md`. Background and history are in `docs/plan/ROADMAP.md`; don't edit its status table in an issue PR.
- **Hevy workout identity** is normalised `(title, startedAt)` (blank title becomes "Workout"), shared by `HevyCsv`, `ImportRepository.prepare` and the `import()` transaction. Exact matches against stored Hevy workouts are reserved first; a stored workout left over at the same start then absorbs one leftover incoming workout, so a workout renamed in History is skipped on re-import. Imported times use the zone saved on the first successful import. Hevy files are limited to 25 MiB and backups to 50 MiB.
- **Strict backup reader** (`BackupJson.read`, batch 1): it rejects non-finite, negative, non-integral and overflowing numbers and routine ids outside 1..`Int.MAX_VALUE`, and `restore()` validates every reference before deleting anything. It is as strict as `BackupJson.write` has always been, so every older backup still restores.
